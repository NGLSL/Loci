# Windows NTFS 阶段 B：独立后端闭环
Status: ready-for-agent
Category: enhancement
Blocked by: None

## Goal

在阶段 A 独立原型证据基础上，交付可评审的 Windows 私有后端：建立库存、查询名称／路径、处理在线变化、停止释放、持久化、跨进程重开并处理离线变化。阶段 B 不修改根 Cargo.toml 或现有共享引擎接口；共享装配等待 proposed ADR 的双方确认。

## Scope and decisions

- 独立 Cargo 项目和 target，Rust 1.99.0、std-only，独立功能工作树。
- 原始 UTF-16、来源绑定、对象及 parent/name 目录项关系；完整路径作为派生结果，硬链接核对全部搜索路径。
- 在线重放按受影响 parent／对象收集并校正目录关系。普通无关卷事件不触发完整范围重扫；目录改名、移入／移出和硬链接变化按实际关系校正。无法解释的情况明确 Pending／重建，不能发布缺失的完整状态。
- 私有试验预算为 32,768 条、8 MiB 序列化库存、64 层；有界批次及明确超限。这些预算与旧共享引擎的 4,096 条限制不同，不能由调整数值宣称百万级产品能力。
- 库存与 journal ID／USN 游标同次原子保存。加载、重放或保存失败保留旧有效库；不兼容格式及来源变化明确拒绝。
- 文件变化仅发生在工程内明确的测试根。卷读取范围和管理员需求显式说明；不创建、删除或调整 journal，不改系统设置。

## Acceptance

- [ ] 原生来源和权限错误包含 OS code；无权限或非 NTFS 明确提出目录扫描 + ReadDirectoryChangesW 的降级限制。
- [ ] 完整闭环通过公开私有接口验证，查询具体名称／路径，停止后句柄释放，重开处理离线变化。
- [ ] 独立目录遍历的完整原始路径集合与稳定截止点库存完全相等；不以 count、checksum 或前 50 条替代。
- [ ] 先完成 1,000，再完成 10,000 个真实文件的工程夹具；目录条目额外计数。在线／离线 add、delete、文件改名、目录改名及硬链接增删均校验。
- [ ] 普通局部变更报告受影响校正范围，证明并非每条卷事件都全量扫描；原生 USN 证据与注入故障分别标注。
- [ ] 损坏／截断、游标失效／journal 更换／回卷注入、预算失败不发布有效完整状态；模拟结果不冒充真实 journal 内核行为。
- [ ] 报告时间、内存、句柄及批次，区分用户进程指标与未测内核开销；取消及异常路径验证适度、明确未测项。
- [ ] 给出固定基线／提交、复现命令、真实通过项、模拟项、阻断项及 100k／1M 的下一轮预算方案。

## Out of scope

GUI、共享引擎装配、Linux 实现、全机默认扫描、自动 100k／1M 创建、合 main、PR、release、系统设置修改。管理员 UAC 每次须有覆盖本次执行的明确授权；先完成可检查的代码与有界 runner，再请求需要的授权。
