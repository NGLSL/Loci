# v0.1 跨模块事件接口契约

> 本文描述原有有界目录验证引擎及其历史证据。4096 条目预算不适用于当前 NTFS 全卷服务的产品上限；服务／普通权限 CLI 的当前入口见 [README](../README.md)。
本项目仅支持 Windows；本文件冻结 Windows 事件输入的最小 seam，不表示产品已经完成。原目录事件模块使用 Rust1.99.0 标准库；当前服务依赖另见 THIRD_PARTY.md。实现定义在 `loci_experiment::events`。已有查询/恢复原型兼容保留。Windows后端与引擎/持久化分别由独立工作树实现，不更改对方文件。

## 路径与事件

使用 `PathBuf` 保存原始拼写/平台OS表示；事件路径相对于调用方明确选择且已canonicalize的根，不含prefix/root/parent组件，不为空。原始路径不lowercase、不拼shell、不转换成绝对索引键。返回路径由引擎将root与相对路径组合。

复用 `Change::Refresh(PathBuf)`、`Remove(PathBuf)`、`Rename {from,to}`。Refresh表示重新检查文件/目录状态，不是内容全文索引；Remove删除库存前缀；Rename保存同一可靠操作的两个相对路径。不要猜测无法配对的rename。

整批路径由引擎在任何filesystem inspection前验证。Windows ASCII冒号表示stream-path，不属于filename条目。引擎当前拒绝不能建立UTF-8查询索引的候选并保留旧结果，后端保留OsString，不做有损转换。单条路径4096bytes、当前实时4096条目（含目录）/1MiB输入/128目录/16深度/4次扫描重试仍保持，不自行扩上限。

## EventSource

`EventSource: Send`，只有一个owner顺序调用poll/stop，不要求Sync。两个方法：

- `poll(&mut self) -> io::Result<EventBatch>`：非阻塞等待语义，只消费已经可用的有界事件；空Watching批次表示当前无可用事件，不表示文件系统完整。
- `stop(&mut self) -> io::Result<()>`：幂等，取消pending I/O并安全确认完成后释放；不能等待下一次文件变化才停止。随后poll返回empty Stopped。Drop也释放同样资源。不能在内核仍使用缓冲或OVERLAPPED时释放它们。异步缓冲与OVERLAPPED必须保持稳定地址，来源在线程间移动也不能改变这些地址。

`EventBatch {changes: Vec<Change>, losses: BTreeSet<Loss>, state: SourceState}`。SourceState为Watching或Stopped。Loss为KernelOverflow/UserOverflow/UnpairedRename/InvalidEvent/WatchLost/BackendRestart。任意loss意味着本批changes不可作为完整切面，引擎丢弃changes并进入有界校正，不发布Validated。Fatal poll错误保留io::Error及OS code，引擎标Failed/保留旧查询，不能把错误当空批；后端释放或通过stop清理。构造失败返回io::Error，不先构造假Watching来源。

`EventLimits::new(max_events,buffer_bytes)` 或Default，默认256事件/64KiB；合法1..256事件、4..64KiB且DWORD对齐，private字段不能绕过构造。max_events()/buffer_bytes()读取。每poll最多8次可用读取（MAX_READS_PER_POLL），达到队列/读取预算表示UserOverflow，不能静默截掉后仍说可靠。每平台最多8来源（MAX_SOURCES）；Windows全局reservation及RAII释放归后端所有。报告OS handle数量，RSS不包含内核对象字节。

## 启动、校正、停止与并发

引擎先安装真实source，再扫描声明root；扫描/构建后再次drain事件。generation变化拒绝候选，loss/不可靠批次走有界校正，单独可靠事件保持增量路径。源创建和重建的gap必须校正，不能恢复原Validated。root自身身份/存在与排除策略由引擎装配负责；来源若观测WatchLost必须上报。Windows递归通知本身不保证报告root目录自身变化。

查询租约持有不可变版本，最多8租约/两代背压。Validated只对应最后观察切面；部分/取消/pending/failed和Stopped有区别。停止或丢弃引擎后留下的query handle必须显示停止监控，不能继续声称持续校正；这属于主实现后续生命周期工作，不是此trait骨架已经做到的声明。

## Windows独立模块交接

Windows工作树从包含此契约的精确提交创建，使用交接时明确给出的独立目录（不要复用独立验收目录、主target或主Git index）。可拥有 `src/windows_events.rs`、`tests/windows_events.rs` 及私有本地任务记录。公开构造固定：

```rust
WindowsEvents::open(root: &std::path::Path, limits: EventLimits)
    -> std::io::Result<WindowsEvents>
```

实现EventSource，root已canonicalize且为明确选择的directory；不要扩大扫描。主实现拥有events.rs、lib.rs、Cargo.toml、main.rs、engine/storage/live/watch/incremental以及公共文档/ignore装配；Windows方返回精确模块提交，由主实现加 `#[cfg(windows)] pub mod windows_events;`，不同时改这些共享文件。生产模块使用 `crate::events`；独立integration测试先定义 `mod events { pub use loci_experiment::events::*; }`，再用 `#[path = "../src/windows_events.rs"]` 导入模块，避免修改共享lib.rs。自己的临时whitelist/测试装配不进入模块交接提交。

优先使用ReadDirectoryChangesW原生递归通知和overlapped I/O，buffer不超过64KiB。create/attrib映射Refresh，delete映射Remove；old/new rename可靠配对才映射Rename。跨读取保留最多一个old-name且有有限期限，不能无限挂起；无法配对、记录长度/offset/UTF-16边界异常、zero-byte/枚举溢出、达到本地预算均上报loss。UTF-16 OsString保持原始表示；reject绝对/逃逸/ADS事件名，不跟随子树link/reparse、不订阅内容/全文。后端对link内部事件的过滤最终由引擎统一排除规则和逐层检查保证。

完成门槛：真实Windows夹具新增/删除/文件与目录rename能收到native批次；unicode/空格/跨buffer和不完整rename的状态可靠；实际停止/drop/错误路径释放OS handles与8-source reservation；停止在空闲目录不依赖制造事件；不把纯decoder测试或模拟overflow当真实kernel overflow。核实取消竞态，保留必要最终证据。不得安装全局软件或改系统参数。

依据：[ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw)、[CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex)。正式release、许可证选择及合main另行决策；本轮只同步功能分支。
