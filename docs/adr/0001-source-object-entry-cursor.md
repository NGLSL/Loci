# 来源、对象、目录项与平台游标

Status: proposed

Windows 实测基线为阶段 B 源码 `e9684d5988b1b963c2091426e998b7f35eeb18b8`，完整交付 `8607bb5584b642dafb9e3edc766b78a63b959f66`。Windows 核心装配所需的具体契约、实际实现与建议的差异及未决项见 [Windows／共享核心交接](../WINDOWS-SHARED-HANDOFF.md)。该交接完成不改变本 ADR 的 proposed 状态。

本记录是 Windows 独立原型向核心提出的契约建议。项目现仅支持 Windows；阶段 B 可以验证下述私有模型，核心装配仍须确认公共契约，本 ADR 保持 proposed。

同一对象可能有多个硬链接，完整路径还会随祖先目录改名变化，因此完整路径不能作为对象的唯一身份。采用来源身份、来源内对象身份及独立目录项关系：每个目录项保存 parent、object 与平台原始 name，搜索路径从目录关系派生。Windows 原始名称保留 UTF-16 码元。显示或查询转换不能改写原始名称。

Windows 原型的来源绑定由卷 GUID、既有 API 提供的 legacy 32-bit volume serial 和选定根对象共同组成；serial 的存储位宽不代表已验证完整 64-bit 卷序列号。对象 file reference 保留其完整返回值及复用区分信息。对象和父对象必须属于同一来源。硬链接的每个搜索路径拥有自己的目录项，USN 单次枚举记录不能代表全部链接名称；实际命名空间和原生硬链接枚举需要共同核对。

共享建议进一步区分来源身份与搜索范围：卷／provider 身份限定对象命名空间，root 对象及原始 scope 限定一次库存覆盖。同卷不同 root 不应让同一物理对象变成两个不同的来源内对象；Windows 私有持久容器当前同时绑定上述信息。分离后的编码与重叠范围策略仍需确认，没有修改现有持久格式。

阶段 B 的私有 EntryId 暂采用 `(parent, object, raw name)` 关系键，改名相当于删除旧关系并添加新关系。共享 EntryId 是否跨改名保持稳定、跨删除重建如何避免身份复用，以及持久键的编码，仍待共享确认；本提案没有冻结公共接口。

游标属于来源。Windows NTFS 保存 journal ID 与 USN；目录递归通知没有等价的持久恢复游标，重启需要校正。来源 identity、搜索范围、完整 inventory 与对应 cursor（若可用）在同一次原子持久更新中提交；重放、权限、预算或一致性校验失败保留上次完整视图并报告 Pending／要求重建。保存失败保留上次持久库并单独报告，不把已成功发布的内存观察等同于已持久保存。journal ID 改变、已保留范围不覆盖游标及游标超出当前边界分别返回明确原因。

选择关系模型增加了路径解析与一致性检查的成本，但避免改名重写所有后代主键及硬链接路径丢失。把完整路径作为缓存可以是后续优化，不能替代来源、对象及目录项的身份关系。小型原型中的稳定截止点校验不等于并发任意写入下的文件系统事务快照，也不提供真实掉电或其他文件系统保证。
